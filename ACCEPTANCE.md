## Documented implementation policies, distinct from PDF requirements

The PDF states the basic attendance, leave and full-month salary rules. The following are agreed project interpretations for unspecified cases, not additional PDF mandates. See AGENTS.md and README.md for full detail:

- Attendance uses local action dates/UTC durations, freezes lateness at check-in, allows nonworking and overnight/overdue shifts, credits only their starting date, excludes today/future from synthetic absence and derives history using current settings/joining dates. No auto-checkout or invented duration.
- Leave types share an annual quota; inclusive ranges stay in one year, start on/after current joining, and must include working days. Pending reserves quota; pending/approved calendar ranges block overlap; rejected replacements are allowed. Saved day counts are audit snapshots while current counts/balances recalculate. Decisions are immutable; stale reviews reopen; deleted requests may be rejected but not approved. Approved working-day leave is paid/excused and actual attendance wins.
- Payroll derives on demand from current salary/settings/joining/approvals, with no stored totals/snapshots. Joining-month gross prorates using the full-month denominator; current month is a full-month projection. Relevant open shifts make their starting month provisional; nonworking attendance and late-only flags add no deduction or pay. No eligible days gives zero entitlement; the defensive zero-denominator branch gives null amounts. Calculations use full precision and display two decimals without assuming currency.
- Helper uses whole supported question patterns, current role/data, completed Monday-Sunday hours by starting date, truthful unknown lateness and separate approved/pending/available balance. Memory-only chat clears on rerender/account/storage errors. Announcements have exact fields and no edit/delete feature.
- Authentication is a learning demonstration: PBKDF2 hashes and user-ID-only sessions do not make browser storage private or tamper-proof. No shared cross-device data, trusted clock, recovery, transactional multi-tab guarantees or production HR protection. Use one editing tab and sample information.
